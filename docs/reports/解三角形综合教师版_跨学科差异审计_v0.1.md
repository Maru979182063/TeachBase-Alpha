## 5. 为什么我不建议按学科拆成多个 skill

因为数学和英语虽然题面差异很大，但顶层工作流其实是一致的：

1. 先看整页视觉结构
2. 识别蓝色挂件/组件边界
3. 确定考点、例题、训练、课后落实的父子关系
4. 再切单题
5. 最后才做局部文字抽取与审核

也就是说：

- workflow 一样
- output contract 一样
- QA 方式一样
- 教师审核入口也一样

真正不同的是：

- 哪些视觉块要当题
- 哪些视觉块要排除
- 哪些跨页续接规则更容易出错

这更适合做成：

- 一个总 skill
- 多个 runtime profile / lesson family rule pack

## 6. 数学样本里暴露出的专属问题

### 问题 A：新考点起始题漏切

在 `考点2：三角形形状判别及解的个数` 中：

- 实际页面上 `例题讲解` 的第 1 题是存在的
- 可在 `annotated_p007.png` 看到组件起始处已经出现 `1.（多选）...`

但最终 question JSON 里该考点只出现：

- `Q2` 到 `Q9`

没有 `Q1`。

这不是人工审核问题，而是 **silent miss**，优先级很高。

### 问题 B：跨页续题吞掉下一题开头

`tq_010`：

- `考点2 / 例题讲解 / Q2`

它的 crop 同时带进了下一页开头的 `Q3`。

证据：

- `tq_010_考点2：三角形形状判别及解的个数_例题讲解_Q2.png`
- `tq_011_考点2：三角形形状判别及解的个数_例题讲解_Q3.png`

前者末尾已经出现下一题题干，后者又从同一题重新开始。

这说明当前续页逻辑在数学跨页推导场景下仍有：

- 续题边界过宽
- 下一题起点截断不够严格

### 问题 C：非题型页面被误切成 `Q0`

`tq_035`：

- `考点4 / 强化训练 / Q0`

实际上不是题目，而是：

- `要点回顾` 思维导图页

这次的好消息是它被标成了：

- `NEEDS_MANUAL_REVIEW`

没有静默入库。

但它仍说明 runtime 需要新增：

- `要点回顾 / 知识导图 / 思维导图` 排除规则

### 问题 D：数学耗时显著更重

这份 33 页样本完整跑完大约用了：

- 10 分钟

这说明数学不是“不能拆”，而是：

- 能拆，但更重
- 视觉切分之后的文字辅助、跨页拼接、导出阶段都更慢

## 8. 最终判断：要不要单独做 skill

### 结论

**不建议按学科拆成多个独立 skill。**

更合适的是：

- 保持一个 `teacher-handout-visual-split` 总 skill
- 在 runtime 中增加不同学科/讲义族的 profile

### 推荐的 profile 粒度

建议至少拆成：

1. `english_reading_teacher_standard`
2. `senior_math_teacher_standard`
3. `junior_math_graybar_standard`
4. `external_nonstandard_scan`

这里的差异重点不是“学科名称”，而是：

- 视觉组件语言
- 题块内部构成
- 跨页形式
- 非题型内容比例

## 9. 哪些规则应该进 runtime，哪些放审核 UI

### 应进 runtime 的

- 新组件起始页的首题保底检测
- 数学跨页续题严格止损，不吞下一题起点
- `要点回顾 / 思维导图 / 知识图谱` 禁切规则
- 公式密集页的题号检测不能只靠单个文字碎片
- 图形默认归属最近题块，除非出现新题号或新组件

### 应放审核 UI 的

- `Q0` 或无题号切片的人工判定
- 低置信度跨页边界微调
- 组件误归属时的手动改挂
- 题块名称和题号的快速修正

## 10. 对你现在产品路线的意义

这次数学样本和上次英语样本一起看，结论已经很清楚：

- 不同学科确实不能只靠一套“纯通用规则”
- 但也没必要上升到“每个学科一套独立 skill”

更合理的产品结构是：

- 一个视觉拆解总 skill
- 一个统一审核台
- 多个学科/讲义族 profile
- 统一输出到题块和组件落库 schema
