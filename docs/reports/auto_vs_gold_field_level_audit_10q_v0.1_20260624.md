## 审查口径

本次不是看“模块大体可不可用”，而是按字段审：

1. `题干`
2. `题干图片`
3. `答案`
4. `解析`
5. `解析图片`

判定标准：

- `通过`：可直接进入数据库或只需极轻微清洗
- `部分可用`：人工一眼能修，但不能直接入库
- `失败`：字段内容错误、缺失、串场或结构失真
- `N/A`：该题不存在独立图片字段需求

## 总结先行

| 解析图片 | 0 | 0 | 5 | 仅统计需要独立解析图的 5 道初中几何题 |

### 最突出的错误类型

1. 字段边界失败
   - 题干里混入答案或解析
   - 答案字段为空
   - 答案字段混入“分析”
   - 题干里串入下一题开头

2. 符号保真失败
   - `△ABC` 被识成 `△4BC`
   - `∠` 被识成 `Z`、`L` 或直接丢失
   - `≌` 被识成 `=` 或 `≤`
   - `∵`、`∴` 常被打散为句点或空白

3. 公式结构失败
   - 分式上下结构被压扁成线性乱码
   - 根式作用范围丢失
   - 上下标、平方、二倍角公式串成 token soup
   - 多步推导链失去先后关系

4. 版面顺序失败
   - 多列选项顺序打乱
   - 页码混入解析
   - 图中字母和正文混读

5. 图片字段未落库
   - 5 道几何题全部存在题图
   - 多道题还存在解析辅助图
   - 当前 `stem_image_path` 与 `analysis_image_path` 全部为 `null`

## 结论

### 1. 当前自动结果的真正短板，不只是“识别错字”

更本质的问题是三层同时失效：

1. 字段切分失效
2. 符号保真失效
3. 图文归属未写回字段

### 2. 对数据库最致命的不是小错，而是这几类错

1. 关键结果值不在答案字段
2. `∠`、`≌`、分式、根式失真
3. 解析链被压扁后无法复原
4. 图没有单独归属到 `题干图片` / `解析图片`

### 3. 这 10 题里相对最接近可用的字段

只有以下几类还算勉强：

- 客观题的单个选项答案字母
- 少数纯文字题干
- 个别几何题的解析主干

但一旦进入：

- 分式
- 根式
- 角符号
- 全等符号
- 多步推导
- 多图证明

自动结果就会快速跌到不可入库。

## 建议下一步

如果你要继续做三天内的测试提交，最值得补的一层不是继续调“整题 OCR”，而是直接把下面三件事列成 runtime 任务：

1. 字段边界校正
   - 先把 `题干 / 答案 / 解析` 分开
   - 禁止题干里混答案和下一题

2. 符号保真校正
   - 优先处理 `△ ∠ ≌ ∵ ∴ √ π 分式`
   - 这批符号要单独做字典与局部复核策略

3. 图片字段回填
   - 几何题至少要把题图和解析辅助图单独存入字段
   - 否则文本就算修好了，图文仍然无法落库
