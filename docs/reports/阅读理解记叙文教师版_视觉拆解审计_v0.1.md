# 阅读理解体裁训练之记叙文-教师版 视觉拆解审计 v0.1

## 1. 审计目标

对讲义 `阅读理解体裁训练之记叙文-教师版.pdf` 做一次真实试跑，验证当前拆解链路离目标能力还有多远。

本次审计坚持以下前提：

- 视觉结构是主骨架
- OCR 只能做补充，不能做主驱动
- 目标不是“尽量识别文字”，而是“稳定拆出结构组件与题块并可落库”
- 教师审核应当是异常兜底，而不是常规流程

## 2. 样本与结论先看

### 样本

- 源文件：`C:\Users\EDY\Desktop\阅读理解体裁训练之记叙文-教师版.pdf`
- 页数：43 页
- 版式特征：
  - 前几页是课程目标、知识梳理、阅读解题思路等大组件
  - 中后段进入多个例题组、题目、解析、易错题、课后落实
  - 尾页存在近空白页

### 一句话结论

当前现状离“稳定且准确的视觉拆解 + 自动落库”还有明显距离，但已经暴露出非常清晰的修正方向：

- 通用主线当前对这份讲义是 **直接失效**
- 英语专用原型能拆出一部分结构，但 **强依赖 OCR、速度偏慢、后半段严重漂移**
- 这进一步证明：后续 runtime 必须继续往 **视觉先行、版式 profile、局部转录、低频审核兜底** 的方向收敛

## 4. 核心发现

### 发现 A：通用主线对该讲义为 0 产出

证据：

- `outputs/ingress_splitter_v0.1/codex_trial_english_narrative_visual_v02_20260623/teacher_visual_question_split_v0.2.json`

结果是 0 anchor、0 segment、0 question。

这意味着当前通用 runtime 不是“效果一般”，而是 **对该类讲义没有可用性**。

### 发现 B：英语专用原型不是通用 runtime，而是强特化 profile 原型

证据代码：

- `tools/english_teacher_visual_dual_extract_v01.py:326-385`

其中 `build_components()` 直接以：

- 第 1 页找“课程目标”“知识梳理”
- 第 4 页找“阅读解题思路”“例题讲解”

作为结构锚点。

这说明它更像：

- 针对某一类英语讲义的试验型 profile

而不是：

- 可以外扩到更多讲义来源的正式 runtime

### 发现 C：英语专用原型依然是 OCR 重流程，不符合“视觉为主”的最终方向

证据代码：

- `tools/english_teacher_visual_dual_extract_v01.py:488-493`

实际流程是：

1. 先整份 PDF 渲染
2. 再整份页面 OCR
3. 再找例题起点
4. 再组组件
5. 再切题

这条链路的问题不是 OCR 准不准，而是 **OCR 参与得太早、太深、太全量**。

### 发现 D：历史产物存在严重过合并

证据：

- `outputs/ingress_splitter_v0.1/english_narrative_teacher_dual_v01/dual_extract_manifest.json`

其中：

- `example_001`：第 4 到第 8 页
- `example_002`：第 8 到第 43 页

`例题 2` 直接吞掉了后面 35 页内容，这在结构上是不可接受的。

这说明当前规则缺少：

- 新组件起点识别
- 大跨度异常截断
- 跨页归属纠偏

### 发现 E：后半段题块明显漂移，甚至开始切答案、词汇和尾部碎片

证据：

- 历史清单共 66 个题块
- 其中第 34 页就出现了 27 个题块起点

这不是正常题页密度，更像是：

- 答案区被误切成单题
- 词汇解释被误切成单题
- 尾部窄条内容被连续误切

联系历史联系图可见：

- 后半段出现大量又细又短、接近无效的切片

这意味着当前单题切分缺少：

- 最小有效高度约束
- 答案区/词汇区排除规则
- 页面功能区分类

### 发现 F：尾页空白处理缺失

第 43 页几乎是空白尾页，但历史结构仍将最后一个题块延续到第 43 页底部。

这说明当前没有做好：

- 空白页检测
- 尾页截断
- 弱内容页降权

## 5. 这和目标需求差多远

如果目标是：

- 教师不做常规拆分
- 系统自动完成大部分结构拆解与题块落库
- 只有疑难样本才进入外包或人工审核

那么当前状态可以概括为：

### 组件级拆分

- 前半段：有一定基础
- 全文稳定性：不够
- 能否直接入库：不能

### 单题级拆分

- 前几题：部分可用
- 中后段：明显失稳
- 能否低审核落库：不能

### 转录层

- 可做补充
- 不适合做主骨架
- 当前参与过深

### 审核压力

- 现状需要高强度人工回看
- 与“只审核困难样本”的目标相反

## 6. 直接指向 runtime 的修正建议

### 建议 1：把 runtime 拆成四层，不再走“先 OCR 再猜结构”

建议正式写成四层：

1. 视觉块检测层
2. 块间归属层
3. 局部转录层
4. 置信度审核层

其中：

- 文字是块的属性，不是块的来源

### 建议 2：为“英语阅读教师版讲义”建立版式 profile，但不要写死页码

这类讲义结构固定，其实是优势。

建议识别：

- 蓝紫色章节挂件
- 课程目标
- 知识梳理
- 阅读解题思路
- 例题讲解
- 易错题
- 课后落实
- 答案/词汇/翻译区

但识别方式应当基于：

- 视觉标签样式
- 相对位置
- 块间上下文

而不是：

- 写死第 1 页找什么
- 写死第 4 页找什么

### 建议 3：OCR 改为“局部、延后、按块触发”

建议顺序改成：

1. 先做整页视觉分块
2. 再做组件归属
3. 仅对候选题块做局部转录
4. 对公式、图文、难块保留图片

不要再：

- 全文先 OCR 一遍再决定结构

### 建议 4：补三类强约束，避免后半段崩坏

至少加上：

- 超长例题组截断规则
- 最小题块高度和最小内容密度规则
- 答案区/词汇区/翻译区禁切规则

### 建议 5：加页面功能分类，再切题

先判断页面是：

- 结构说明页
- 例题讲解页
- 题目页
- 解析页
- 词汇页
- 课后落实页
- 尾页/空白页

再决定是否进入单题切分。

### 建议 6：审核只留给低置信度异常

这份样本已经说明，审核台应该只接管：

- 超长跨页块
- 极窄切片
- 组件边界冲突
- 文本置信度过低
- 图文关系不明

而不是让教师从头帮忙拆。

## 9. 最终判断

这份讲义的试跑结果非常支持原先判断：

- 题目型讲义系统必须以视觉结构为主
- OCR 不能做主骨架
- 当前现状还没有达到“低审核自动落库”
- 但已经足够说明下一步应该修哪里，而且方向很明确

如果后面继续推进，优先级不该是继续抠 OCR 准确率，而应该是先把：

- 视觉块 schema
- 页面功能分类
- 块间归属规则
- 异常切片约束

这四件事做稳。
