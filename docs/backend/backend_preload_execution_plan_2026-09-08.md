# 后端灌装前执行计划

日期：2026-09-08。版本：分阶段批准 v3。状态：G0/G1已验收；G2/G3获准实施并完成隔离验证，现提交第二阶段验收。

用户最新阶段门禁优先于以下原始路线图：本轮G2/G3结束后停止，第二阶段结果见[验收报告](../audits/g2_g3_stage_acceptance_2026-09-08.md)。生产stable-source registry保持为空，one-shot不自动升级。G4/G5仅保留既有设计，G6本轮不实施；不迁移或灌装原候选库。

依据：[灌装前审计](../audits/backend_preload_readiness_audit_2026-09-08.md)。实现基线：`3a3f59d`。目标是在加工链迭代期间，先完成可独立开发的后端约束、接收与恢复能力，再完善审核和检索。

## 1. 范围和审批含义

本计划批准后允许进行后端实现、追加迁移编写、隔离数据库测试、文档更新和当前工作分支提交。实际候选库的迁移及大规模灌装在提交演练结果后另行确认；不把测试批准写入真实题库。

实施使用独立工作树和测试数据库，保留现有 52 题作为固定回归输入。开工先复核其他任务更新与迁移序号，避免与同步加工开发相互覆盖；迁移文件使用当时下一个可用版本，不预占 V009 或改写已执行的 V001—V008。

路线图保留 G0—G6 的依赖说明，实际实施权限以本文件开头的用户阶段门禁为准。

工期不在未经实现拆解时给出固定天数；G0 完成后按实际接口和迁移范围更新估算。稳定来源锚点未确定会限制跨轮灌装，不妨碍 G1、G3 和接口样例推进。

## 3. 详细执行与验收

### G0：交付合同和稳定身份

交付物：后端接收 schema、加工到接收适配字段表、成功/冲突/不完整包样例和 Golden 测试夹具。已有候选入口继续可用，新合同采用明确版本入口；旧入口不承诺新批次能力。

必须明确：importRequestId 的重试范围、服务端包摘要规则、稳定题目键、内容 schema/哈希版本、来源证据、文件相对路径/哈希、标签体系版本和缺失字段语义。模型/profile/runId 作为来源记录，不直接生成稳定题目身份。

身份验收矩阵：

| 场景 | 预期 |
| --- | --- |
| 相同请求 ID、相同包摘要 | 返回同一接收结果，业务写入不增加 |
| 相同请求 ID、不同包摘要 | 409，无新业务写入 |
| 不同请求、稳定题目键相同、内容相同 | 同一题/修订，追加导入观察 |
| 稳定题目键相同、内容变化 | 同一题新增修订，旧批准指针和快照保留 |
| 只改变模型或加工 profile，内容相同 | 不产生新的题目或内容修订 |
| 缺可靠稳定身份 | 明示仅支持一次性候选身份，不按内容相似自动合并 |
| 加工改变拆题/合题边界 | 显式冲突或新身份，不能按新序号覆盖旧题 |

稳定锚点由加工方提供并声明稳定性，后端用重跑夹具验证。没有该协议时，不宣告“可重复加工后自动更新原题”。

### G1：主标签唯一性

先输出已有数据冲突报告；遇到冲突迁移中止并列出精确 ID，不自动选胜者。明确维度、版本与历史查询关系后，用追加迁移建立数据库约束，服务层给出可辨识的错误码。

本期行为：已有同一绑定重放成功；已有另一主标签时返回 409，旧主标签不变。显式替换及降级/删除策略留给后续接口，不依赖尚未决定的产品行为来放行约束。

验收：两个并发不同 primary 绑定最多一个成功；不同维度可独立绑定；同绑定重放不增行；历史版本查询不混淆当前有效标签；迁移遇到既有冲突可诊断；52 题真实流程中的已知失败转为通过，同时保留原失败历史报告。

### G2：预检及同步接收回执

新增只读预检入口，输出包版本、检查时间、服务端计算的摘要、逐题 issueCode/fieldPath/evidence、阻塞或警告级别。结果不得声称已经写库或已经预留身份。原文件未上传可做结构预检；只有文件齐备并核验后才允许完整预检通过。

规则：不支持的协议、无效结构、文件缺失/字节哈希不符、身份冲突、无效标签引用和非法状态属于阻塞；缺知识点、难度、页码/坐标可作为显式不完整待审核候选，不能伪造默认值或自动批准。有效性以结构合同为准，不判断教学语义。

复用领域验证，避免预检和写入各自维护两套规则。服务端核对真实引用文件与内容摘要；历史声明的来源哈希不得直接充当可信包签名。提交时重复易变化条件的校验，数据库约束负责并发仲裁。

新增持久化接收记录，按 workspace + importRequestId 唯一，保存服务端摘要、结果及逐题映射。同步处理保持每批最多 100 题，业务表与成功回执原子提交；失败诊断不伪造成功回执。未提交事务可重试，提交后响应丢失可通过相同 ID 查得原结果。

这一步包括批次级重放与查询，不包括后台队列、跨批 worker 或逐题断点续跑。失败仍按单批事务处理，避免把 Release Seed 的自动批准假设带入候选导入。

验收：结构预检不新增题目/修订/审核任务；第 2 题非法不留下第 1 题；预检后文件变化仍拒绝；同 ID 同包并发只提交一次；同 ID 异包冲突；提交前进程失败可重交；提交成功而客户端超时可恢复原回执；跨工作空间文件拒绝。已有不可变修订哈希不被重算覆盖。

### G3：灌装恢复与运行保障

先完善 DB 与 storage 的一致性备份，记录文件清单、哈希、迁移版本、备份时间和提交水位；不能假设并行复制目录与数据库备份天然一致。首版允许暂停接收以形成明确恢复点。

对账报告区分已被题目引用、已登记未引用、磁盘未登记及丢失文件。仅报告，不自动删除重试可能需要的资产。新副本恢复后核验数据库关系与实际字节。

区分进程存活、接收入库就绪和导出就绪；渲染器故障应阻止导出，不应误判所有存储功能不可用。日志关联请求、批次、题目和导出任务；指标不把题目 ID 当高基数标签，也不记录密钥或全文题干。

容量先以 1千/1万/10万题的合成元数据和 1/5/10 并发作分级工程测试，另保留真实图片/公式导出测试。记录硬件、数据体积、索引、p50/p95/p99、错误率和资源峰值；合成测试不证明教学质量。

拟定本地联调门槛：1万题、5 并发、每页 50 条的约定查询 p95 ≤ 1 秒，非预期服务错误为 0；10万题用来发现拐点，不作为生产容量承诺。导出记录排队和执行时间、资源峰值，不套用检索阈值。达不到门槛要报告原因与调整，不改测试口径掩盖失败。

验收：新副本可恢复、题目/来源/审核/文件一致；提交边界故障不出现“成功回执但题目缺失”；健康状态正确反映依赖故障；输出容量和恢复耗时报告。RPO/RTO 记录实测值，正式生产目标另定。

### G4：审核队列与批量治理

补队列列表/详情及状态、批次、来源、结构化缺项筛选；沿用已有单题状态机和精确修订哈希校验。分页明确是实时队列，不承诺并发变更下整个遍历是固定快照。

批量审核建议每批最多 100 条，各条带 reviewCaseId、expectedContentHash、决定和操作依据。逐题独立事务，响应逐条列成功、已处理、冲突、失败，不能用 HTTP 200 代表全部批准。同一审核决定的重试行为需要显式定义，不能把不同决定当作同一次请求。

新增待审核修订产生相应审核任务，保留旧批准修订和快照；旧任务是否过时在队列中清楚标识，不能因模糊“自动重新审核”而修改已批准的历史事实。审计记录行为和来源；可信身份完成前仅限受控本地操作者。

验收：两个操作者对同案相反决定最多一个生效；混合批次逐题结果准确；错误哈希拒绝；缺项筛选可回溯结构化证据；新修订不覆盖旧发布内容；所有批准只在测试副本进行。

### G5：搜索投影及回填

已有结构化筛选、游标和 trigram 索引继续复用。新增材料/题干/选项/子问的明确投影；答案解析检索沿用已定义权限和使用场景。投影是派生数据，题目正文和原始 LaTeX 为原始记录。

标签筛选须等 G1 的维度规则成立，再明确版本化关系表与旧修订内标签字段的查询优先级。新增来源和批次筛选；引用状态是精确关联存在性，不能推断教学相关度。

追加投影版本，先回填、对照，再切换；支持重建及回到旧读路径。状态更新、题目修订及标签修改不能留下无法发现的陈旧投影。首版可使用同事务更新或明确的可补偿机制，方案在该包设计记录中固定。

验收：只能在选项/子问命中的样例可搜到；待审核不进入默认批准检索；旧批准指针保持稳定；相同时间记录分页无重复/遗漏（固定数据集）；跨工作空间不泄露；重建前后结果一致；满足 G3 的约定查询基线。

语义搜索、错字容错、自动相似题合并、模型分类和知识标签生成不在本期范围。只对文本做结构化提取，不使用正则推断题义。

### G6：共享试用的身份前置条件

采用可信服务端身份来源和内部认证适配，拒绝客户端冒充 actorUserId；定义导入服务账号、查看、编辑、审核和管理动作，以及 workspace/private 资源边界。无需先选最终 OIDC 供应商，但不能把固定可伪造请求头当认证。

验收覆盖未认证访问、冒用他人身份、只读角色写入、跨工作空间访问、私有讲义和资产导出访问。通过前保持共享试用门槛未关闭。最终 OIDC、生产密钥轮换和部署授权另行安排。

## 4. 与加工开发协同及变更控制

后端工作集中在 Java 领域模块、追加迁移、适配合同和验证工具。加工方继续改节点、prompt、边界拆分、标签模型和题源生成；交付到稳定出口时再用版本适配连接。

协同检查点仅三个：G0 确认稳定身份/字段语义；G2 用一份新版真实包核验接收；最终用四链各一包补齐跨链验收。若某条链未提供样本，标记未覆盖，不能借 DOCX 通过代替。

未知版本拒绝且给出原因；可选新增字段按明确扩展合同处理，不静默丢掉教学正文。受影响的字段和迁移采用独立提交，不覆盖其他任务的未提交更改。

## 5. 迁移、验证与交付规则

数据库变更先在空库及真实备份恢复副本验证，报告锁等待、冲突数据、回填时间和应用兼容性。优先追加/回填/切换，回退应用读写路径时保留新表及审计事实；不使用删除真实修订作为回滚。

每包交付代码提交、迁移及回退说明、测试命令和机器结果、未关闭项。改到哪个模块，执行对应门禁；最终对集成版本执行 52 题流程及相关后端门禁，记录提交 SHA 和证据哈希。已有单主标签失败必须如实关闭，不能改成“预期失败”通过。

审核队列、请求回执等新能力增加必要故障/并发测试，不为纯文档和低影响修改堆测试。实际灌装前另交一次放行报告，列明当前仍开放的身份、来源和权限限制。

## 6. 本次建议批准的具体决定

1. 实际批准范围：第一阶段 G0/G1，验收后才可进入第二阶段 G2/G3，第二阶段真实包隔离验证后再次停门；G4/G5 保留设计，G6 本轮不实施。
2. 主标签普通绑定冲突返回 409，暂不实现隐式替换。
3. 缺知识点、难度、坐标可入待审核并标记缺项；无效引用、结构或字节哈希属于拒收。
4. 新灌装入口先做同步有界提交与持久化回执，异步调度另设工作包。
5. 批量审核采用逐题事务和逐项结果；不以整批请求成功掩盖部分失败。
6. 身份合同无法证明稳定时，仅允许明示的一次性候选流程，不自动归并重加工结果。

本轮按最新批准仅实施 G0/G1，第一阶段交付后停止，等待用户验收。
