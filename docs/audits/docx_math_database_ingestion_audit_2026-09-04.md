## 衔接实现与发现

新增 `/api/v1/ingestion/candidate-batches`：调用 question、source、review、fileasset 的公开模块端口，单事务建立候选及审核关联，不直接写业务表、不使用 Release Seed 的批准路径。专用本地验证环境的身份锚点使用明确的启动初始化 SQL。

新增 Python 适配器：先校验结构、保留文件和原始证据，再调用文件登记与候选接口。它只映射已有结构；没有通过正则、词表或教学语义启发式决定题型、标签或题目边界。

首次适配发现：原 schema 面向模型输出，但最终编排器追加了对象形式的 `normalization_actions`、覆盖报告及 `READY_WITH_COVERAGE_WARNINGS` 状态，直接套原 schema 会报错。已为最终出口建立显式扩展合同；未知顶层字段继续拒绝，警告状态仍待审核。没有删字段或改成 READY 来换取通过。

没有可靠跨轮身份时，以文档哈希、题包文件哈希、题组 ID 共同定位候选。这样相同题包重试不重复建题，重新切题后的同序号不会覆盖此前题目；不同轮次之间的语义去重仍未实现。
