## 2. 三类键的职责边界

| 字段 | 负责 | 本轮边界 |
| --- | --- | --- |
| importRequestId | workspace 内的提交/重试身份；同一重试复用随机 UUID | 已验证包摘要差异；持久化回执和 HTTP 重放冲突待 G2 |
| stableQuestionKey | 已登记来源直接提供的 opaque 持久题目 ID，以 workspace/sourceSystem/来源键命名空间限定 | 生产稳定来源注册为空；不猜测或生成稳定键 |
| contentHash | 按独立 tb-content-v1 计算规范内容摘要；命中题目后判断修订 | 不充当题目身份，不覆盖现有 Java 历史 revision 哈希 |

one-shot 身份为包实例 UUID＋随机 candidateId，并加 workspace/sourceSystem 作用域；stableQuestionKey 必须为 null。题号、顺序、文本相似度、正则、启发式均不参与稳定身份判定。itemKey 只定位包内项目。

## 3. 身份验收矩阵实测结果

G0 共 32 项纯合同测试通过，[机器结果](../reports/g0_identity_contract_gate_20260908.json)。其范围是 schema、键和哈希计算、结构拒绝条件，不是数据库接收流程。

| 场景 | 本轮实际验证 | 未实现的后续环节 |
| --- | --- | --- |
| 同请求 ID、同包 | 摘要和身份一致 | G2 持久化返回同一回执 |
| 同请求 ID、不同包 | 包摘要不同 | G2 HTTP 409 与事务保证 |
| 新请求 ID、同包 | 包摘要、题目身份、内容摘要保持 | G2 跨请求业务去重 |
| 新包、相同正文、one-shot | 身份不同，内容摘要可相同 | 不承诺跨轮自动合并 |
| 包内显示序号/itemKey 改动 | 不改变候选身份 | 无语义身份猜测 |
| 已登记测试来源，仅改 profile/run | 身份和内容摘要不变，交付摘要变化 | G2 导入观察持久化 |
| 已登记测试来源，同键改正文 | 身份相同，内容摘要变化 | G2 新合同到规范 revision 的写入映射 |
| 相同正文、不同稳定键 | 不合并 | 不做相似题自动归并 |
| 拆题后两项重复使用同身份 | 拒绝重复身份 | 拆/合生命周期待加工方定义 |
| 未登记稳定来源/版本 | 拒绝，不相信包内自报稳定 | 真实来源注册需另有证据 |
| 已登记测试来源缺 anchor 字段/稳定原文键 | 拒绝 | 不补造 anchor |
| 标签建议或页码证据变化 | 内容摘要不变，交付摘要变化 | 不覆盖旧 Java 哈希 |
| 标题、选项、子问、教学说明变化 | 内容摘要变化 | 仅验证交付合同 |
| Unicode、LaTeX、对象字段顺序 | 黄金字节与规范化结果一致 | 未来 Java 接入需复用跨语言黄金向量 |

稳定来源的通过案例全部使用明确的合成注册夹具；没有把它们写入生产注册表。既有规范域的同来源键/修订、审核和导入观察行为另由原有 governance 门禁回归通过，但不能等同新 G0 接口已经落库。
