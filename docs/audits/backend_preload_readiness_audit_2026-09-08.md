## 1. 结论与适用范围

后端已有可重复验证的候选存储、审核状态转换、题篮、固定修订引用和文档导出流程，具备继续联调的基础。可以一边修改加工链路，一边完善数据库约束、受控灌装入口、审核接口和运行保障。

批量灌装前最关键的问题是：重复加工后的题目身份、可查询的批次接收记录、入库预检与写入一致性，以及数据库和文件的恢复能力。主标签唯一性必须在正式写标签前关闭。可信身份与动作权限必须在多人或共享网络试用前落实。

目前仅适合受控本地候选试验，不具备无人值守、反复重加工的大规模灌装验收结论。正式生产仍有认证、四链样本、容量、部署及运行恢复等独立门槛。

此前对话中的 80%/70%/55%/35% 没有量化评分模型，本报告不沿用。测试通过比例也不能换算为系统完成度或服务可用率。

### A01：约束与标签切换应分别处理

`V005__question_governance_foundation.sql` 仅限制同题修订、同节点、同关系类型重复；`JooqTaxonomyRepository.assign` 不能阻止另一个节点成为 primary。真实测试已产生 primary_count=2。

项目合同要求“同一 taxonomy 维度最多一个 primary”。执行前需把维度如何映射到 taxonomy_key、版本和查询语义写清楚，不能把版本 ID 默认为全部维度定义。旧版本历史必须可追溯，跨版本有效主标签也必须无歧义。

本次建议审批的行为是：普通绑定遇到第二个主标签返回 409，已有绑定重放成功；不自动降级、删除旧主标签。显式切换 API 另列后续范围。该方案可先防止新增冲突，不能宣称已完成所有标签维护需求。

### A02—A04：一次重交可靠，不等于重复加工可靠

`tools/import_docx_math_candidates.py` 使用整包哈希构造 externalKey，来源键包含文档哈希、整包哈希和题组 ID。相同包重交已验证幂等；包发生变化后，原来未变化的题也可能获得新身份。这是当前保守适配行为，不应改成按序号猜测同一道题。

已有 [ADR-04](../architecture/adr/ADR-04-ingestion-identity-idempotency-revision-dedup.md) 明确区分三个键，并规定没有可靠身份时不能自动合并。本次计划落实该边界，不要求加工节点先统一内部实现。

`CandidateBatchRequest` 当前每批最多 100 题，没有持久化批次标识。`CandidateBatchService` 在单事务内写题目、来源和审核任务；数据库失败能整批回滚，但预先保存、登记的文件不随该事务撤销。保留文件有利重试，后续需要可见的对账清单，不能立即当作垃圾删除。

`QuestionService` 会重算并核对 contentHash；另外两类调用方提供的 sourcePayloadHash/importEnvelopeHash 当前仅校验格式。新批次的可信包摘要必须由服务端按版本化规则计算，不能把这些现有字段当成已校验的整包签名。现有内容哈希还含分类等字段，不能直接换公式后覆盖历史哈希。

预检是检查时刻的结果，写入前状态仍可能变化。真正提交必须重复关键校验，并由事务和约束最终仲裁；预检通过不能代替提交时的权限、文件及身份校验。

### A07—A09：已有基础应增量完善

不需要重建现有游标和基础筛选。新投影要补齐选项/子问，保留待审核与已批准指针隔离，并明确标签关系和旧修订内标签字段谁是查询依据。批次、题源和标签筛选可以增加；是否存在可用值必须如实显示。

可信身份工作可以与加工链并行，不需要先选择最终 OIDC 供应商。多人试用前必须执行；单机维护试验不能作为共享网络部署的授权。

## 4. 加工链与后端的责任边界

| 加工链提供并版本化 | 后端负责 | 双方只需对齐的交付边界 |
| --- | --- | --- |
| 题干、选项、子问、答案、解析及媒体引用 | 结构校验、内容保存、修订、审核、引用与导出 | 内容 schema、字段语义、未知字段处理 |
| 稳定外部 ID 或声明稳定的来源锚点 | 身份匹配、导入观察和修订去重 | sourceSystem、locatorContractVersion、拆题/合题处理 |
| 来源证据、可用的页码/坐标/裁图 | 来源登记、文件核验、完整度展示 | 可选与必填证据、路径及媒体合同 |
| 模型标签建议、置信度、模型/策略版本 | 标签约束、审核及有效标签查询 | 分类体系版本、主副关系、建议与确认的区别 |

教学语义、题目相似度和标签判断不使用正则、词表或序号猜测。代码只执行结构、引用、字节、哈希、身份合同与状态规则。合成数据只用于工程容量验证。

## 5. 本次审核需要决定什么

建议按配套计划批准后端工作包 G0—G5，其中 G0 固定交付合同，G1—G3 构成受控灌装的最低门槛；G4—G5 补齐审核和检索。可信身份工作包 G6 在多人试用前完成，可独立并行。

批准内容包含：主标签冲突返回 409、缺知识点/坐标可保存为显式不完整的待审核候选、批量审核逐题事务并返回逐项结果、新批次回执采用同步有界提交。自动知识点分类、语义去重、加工自动调度和真实题目的批准不属于本次实施授权。

实际大规模灌装仍需提交 G1—G3 的结果及尚未解决的身份约束；本报告审核通过仅启动开发与隔离验证，不自动启动真实数据灌装或生产发布。
